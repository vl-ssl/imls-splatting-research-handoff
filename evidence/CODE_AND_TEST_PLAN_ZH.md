## RefReal适配的明确限制

原始3DGS已有输出不含本项目前处理额外opacity正则，本轮不重跑该前置损失。相机拆分为132/19、138/20、106/16。初始化修正后重新训练原始IMLS和OP，保障五方法共同初始化；旧20k模型保留并标旧初始化条件。完整点集meshscale仍为8/132/20，sedan离群点造成的低世界分辨率仍须披露，不以裁切前景偷偷改变完整场景任务。

后续法线参数和模块保留；COLMAP原数据未提供GT法线，所以法线GT损失没有可用监督，不等于删除模块。没有可靠前景mask时，关闭基于GT mask的轮廓损失，避免用人工全1mask造监督。这与关闭前置opacity正则是两件不同的事。

V32原方案以真实alpha/GT法线进行几何精修，这里无法严格复现。新队列明确采用**V32无GT适配：冻结外观，以RGB和已有位移锚定项短程更新几何**，不能称为原V32同监督复现，也不是本轮新的边界算法；结果必须与V6分别报告。当前V4/V6的SSAA2对原始/OP的SSAA1属于完整流程差异，不能用作单因素因果结论。

新增`tools/check_refreal_memory_shading.py`：对非零随机参数、混合/空覆盖块、训练及推理比较输出，并检查28/34/41个参数梯度和4个输入梯度。三版本检查通过；输出最大差不超过约2.33e-10，参数梯度最大绝对差约1.91e-6。恒零冻结分支跳过也通过输出/活动梯度对照。这些小输入检查不替代全场景验证。

## RefReal完成后：边界候选已实现，进入受控探针

16:30检查确认五种IMLS流程15项及已有3DGS三项全部评价完成；18项的GT字节hash、图名、分辨率逐项一致，完整结果见`REFREAL_RESULTS_ZH.md`。此后才修改边界代码和启动测试。

- `utils/opaque_boundary.py`：`prepare_target`生成真实覆盖率目标的符号距离和亚像素交点；`visible_segments`从边界像素的第一命中三角形提名真实边，再以短段的内侧三角形ID、外侧背景和三处采样验证可见性，拒绝同属前景的内部三角边；`boundary_terms`实现有界区域权重和非饱和双向Huber距离。以上是边界监督，不是前置高斯透明度正则。
- `arguments/__init__.py`、`train.py::training`：新增区域/边段权重，默认关闭；固定点集的位移上限、可选训练保留视角、独立边界梯度记录。原法线和其它损失保留；将GT法线移到预测法线设备，修复CPU保存训练图像时的设备不一致。首个失败探针保留日志，未产生正式模型。
- `tests/test_opaque_boundary.py`：矩形真实边与内部对角线、远端边界梯度方向及有限差分、无支撑/无GT、实际CUDA光栅梯度共四项。AutoDL四项通过；本地CPU通过三项，CUDA项按环境跳过。
- `tools/run_opaque_boundary_20261105.py`、`evaluate_opaque_boundary.py`：在隔离目录`/root/autodl-tmp/opaque_boundary_20261105`固定现有V32输入、核、域、网格、法线监督、渲染分辨率。car和coffee先做零更新、200更新匹配控制、V38距离对照、区域项、边段项与组合；从训练源ID每8个留一作微调阶段验证。历史源检查点已见过这些训练视角，故这不是独立测试。未用正式测试视角选择权重。

探针选择规则（读取结果前固定）：相对200更新控制，两个场景F2都不应降超过0.001、ASSD都不应增超过0.05px，且至少一个场景F2增加0.002或ASSD减少0.05px；各场景同时核对缺失/多余覆盖、共支持法线（允许0.1°的初筛容差）、PSNR（0.05dB）与标准LPIPS（0.001），不以单图或IoU获益掩盖退步。初筛容差是明确的工程门槛，并非显著性声明。通过后固定同一个候选，才进行六场景完整测试；未通过时优先检查缺口是否无支撑，不按场景拼权重或继续用测试集反复调参。

实现该规则的`tools/select_opaque_boundary_probe.py`对缺失和多余覆盖各采用0.001绝对容差，用逐帧完全相同的可见像素计算法线差。若多个候选通过，依次按等权F2、ASSD、LPIPS选择。选择脚本拒绝正式测试分割。

同一轮增设独立的零更新提取域对照：`--phase domain-audit`在相同V32 PLY/外观、相同评估配置及相同13个训练保留视角上，用已有`aligned_mesh_domain`扩大提取盒。新网格保持体素间距和奇偶，原格点不发生半体素偏移；额外留5体素保护边界。逐图验证GT hash和检查点hash相同。这是裁切因素检查，单列于边段损失结果。

`tools/audit_opaque_boundary_support.py`读取已核实帧身份的训练保留视角覆盖图，统计缺失连通区域、距预测覆盖超过8像素的缺失量。对Ref-NeRF原生视差同时测试`1/Z`和`1/射线距离`，显式处理1/255量化；仅将跨多个训练视角且无背景冲突的样本纳入候选支撑距离。该工具只做读侧审计，不写点云。car缺失172,441个像素（跨13视角累计），其中131,750个距当前覆盖超过8像素；但约26,000个已覆盖的参考样本中，两种视差解释仅有3/0个通过严格跨视角检查。该协议未建立足以指导补点的深度可靠性，不能将零通过解释为三维点不存在。

car的配对初查：200更新后，各候选点位移中位约0.089体素，P99约0.43体素，最大值受0.75体素限制。区域项与边段项的首步梯度都到达点坐标和法线；区域项对照变化为F2 +0.000324、ASSD −0.004001px，组合项为F2 −0.000252、ASSD −0.005138px。远端像素缺失与近端位移门槛不同尺度；不据此断言放松限位就能恢复正确几何。独立读取初始PLY和检查点中心，旧提取盒外点数为car 18,871、coffee 2,885，实际裁切效应仍需零更新配对。
